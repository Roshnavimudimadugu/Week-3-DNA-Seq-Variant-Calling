# Post-processing FreeBayes Calls

## Objective

Before analysing and annotating the variants detected by FreeBayes, the multisample VCF file was post-processed to resolve incompatibilities between FreeBayes output and downstream analysis tools.

Two main objectives were:

1. Split multiallelic variant records into separate records.
2. Left-align and normalise indels.

---

## Why Is VCF Post-processing Necessary?

Some genomic positions can contain more than one alternate allele. These are called **multiallelic sites**.

For downstream functional annotation, it is useful to represent each alternate allele as a separate variant record.

Indels can also have multiple possible representations depending on their position within repetitive sequences.

Therefore, indels were normalised to ensure that they were represented consistently and could be compared correctly with variants stored in public annotation databases.

---

## Tool Used

**bcftools norm**

The `bcftools norm` tool was used to normalise the VCF file generated by FreeBayes.

---

## Input Data

The input dataset was:

- The multisample VCF file produced by **FreeBayes**

This VCF contained variant and genotype information for:

- Father
- Mother
- Proband

---

## Parameters Used

The following settings were used according to the Galaxy tutorial.

### VCF/BCF Data

The VCF output generated by FreeBayes.

### Reference Genome Source

**Use a built-in genome**

### Reference Genome

**Human: hg19**

### When Any REF Allele Does Not Match the Reference Genome Base

`ignore the problem (-w)`

### Atomize

`Do not atomize`

### Left-align and Normalize Indels

`Yes`

### Deduplication

`do not deduplicate any records`

FreeBayes does not produce duplicate variant calls, so no deduplication was required.

### Multiallelic Sites

`split multiallelic sites into biallelic records`

### Variant Types to Split

`both`

Both multiallelic:

- SNP records
- Indel records

were split into separate biallelic records.

### Output Type

`uncompressed VCF`

The output was kept in human-readable VCF format.
