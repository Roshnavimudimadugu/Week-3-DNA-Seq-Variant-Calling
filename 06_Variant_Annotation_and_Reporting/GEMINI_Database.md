# Generating a GEMINI Database

## Objective

After functional annotation using SnpEff, the annotated multisample VCF file was used to generate a GEMINI database.

The purpose of this step was to store:

- Genetic variants
- Variant annotations
- Genotype information
- Family relationship information

in a format that could be efficiently queried to identify potential disease-causing variants.

---

## What Is GEMINI?

**GEMINI (Genome MINIng)** is a framework for annotating, storing, querying, and analysing genetic variants.

Unlike SnpEff, which adds annotations directly to a VCF file, GEMINI:

1. Extracts variants from the input VCF.
2. Adds additional annotations from its bundled annotation resources.
3. Stores variants and annotations in an SQL database.

This makes it possible to perform efficient queries on the variant dataset.

---

## Why Was GEMINI Used?

The analysis involved a family trio consisting of:

- Father
- Mother
- Proband (affected child)

The multisample variant data contains genotype information for all three family members.

By incorporating pedigree information into the GEMINI database, variants can be filtered according to inheritance patterns that are compatible with the observed disease phenotype.

---

## Input Data

The GEMINI workflow used:

### 1. SnpEff-Annotated VCF

The annotated multisample VCF produced during the functional genomic effects step.

This file contained:

- Variant information
- Genotype information for the father
- Genotype information for the mother
- Genotype information for the proband
- Functional annotations generated by SnpEff

### 2. Pedigree Information

A pedigree file in **PED format** was used to describe:

- The relationships between family members
- The affected status of each individual

This information allows GEMINI to perform inheritance-based variant analysis.

---

## Tool Used

**GEMINI load**

The `GEMINI load` tool was used to:

- Extract variants from the annotated VCF
- Add GEMINI annotations
- Store variants in a GEMINI database
- Incorporate pedigree information

---

## Output

The output of this step was a **GEMINI-specific database**.

This database contains:

- Variants
- Functional annotations
- Additional human variant annotations provided by GEMINI
- Genotype information for the family trio
- Pedigree information

The GEMINI database can then be used with other GEMINI tools.

---

## Why Use a Database Instead of Only a VCF?

A VCF file can store extensive variant information, but it can be difficult to efficiently query and filter manually.

The GEMINI database allows variants to be queried according to criteria such as:

- Functional impact
- Gene annotations
- Clinical annotations
- Genotypes across family members
- Inheritance patterns

This makes it easier to prioritise variants that may be responsible for the disease.

---

## GEMINI Tools

The GEMINI framework contains several tools.

Some important tools include:

- **GEMINI load** – creates a GEMINI database from a VCF file.
- **GEMINI query** – performs flexible variant queries.
- **GEMINI gene-wise** – performs gene-based variant queries.
- **GEMINI inheritance pattern** – identifies variants according to inheritance models.
- **GEMINI database info** – provides information about the contents of a GEMINI database.

For this workflow, the database created using **GEMINI load** was subsequently used for inheritance-based candidate variant detection.
